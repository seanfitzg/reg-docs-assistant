# Header/footer stripping is automatic; other text cleanup is manifest-flagged

Repeated headers/footers (a line that appears verbatim on at least 3 pages — or on every page, for a document shorter than that) are stripped automatically by the ingestion pipeline. Other extraction noise found to be document-specific — the Financial Stability Review's Irish-language duplication of every section, the DP7 discussion paper's repeated navigation-tab chrome — is instead declared as an explicit manifest flag per document, alongside its chunking strategy (ADR-0014) and metadata (ADR-0013).

The automatic rule also covers page numbers, including a "Page " prefix (e.g. DP8's real running footer, "Page 5", "Page 6", ...) as well as a bare number alone — found necessary while implementing issue #6, since a prefixed page number is neither a bare digit nor a line that repeats verbatim (the digit itself changes every page), so it needed its own equally mechanical rule: a line that's nothing but an optional "page" word and a number is never real content, regardless of document.

These aren't the same kind of problem. "This exact line repeats verbatim, more than a couple of times" is a safe, mechanical pattern with no real judgment call or false-positive risk worth guarding manually — real prose essentially never repeats itself word-for-word three separate times, anywhere in a document. (This rule went through two wrong guesses before landing here. It was first written as "every single page"; implementing issue #5 against the real CP54 PDF found its running header only printed on the 15 pages covering its discussion section, not the 81 pages of appended draft Code text that make up most of the document, so an exact-every-page rule could never fire on it. "A majority of pages" was the next guess, and also failed the same real document — 15 of 96 pages is nowhere near a majority. A small absolute count, independent of how long the document is, is what actually holds up.) Deciding "this is Irish-language duplicate content, not real content" or "this is navigation, not a heading" is a judgment call that risks silently mangling some future document that merely resembles the pattern — the same failure mode already ruled out for chunking strategy and metadata, for the same reason: the person adding a document is already reading it once, so naming its quirks there is cheap, and far cheaper than debugging silently-corrupted Chunks later.
