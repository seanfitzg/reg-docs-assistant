# Chunking strategy is chosen per document in the manifest, not auto-detected

Each manifest entry names its chunking strategy from a small closed set (e.g. `clause_numbered`, `heading_sections`, `academic_sections`), picked by the person adding the document, rather than the pipeline sniffing extracted text at parse time and guessing.

A corpus structure survey found real heterogeneity that one algorithm can't serve: Consultation Papers have decimal clause numbering ("1.1", "Chapter 5, Provision 12"), several other document types (discussion papers, the Economic Letter, the Financial Stability Review, the Annual Report) are narrative prose with only free-text headings, and the Research Technical Papers have academic section numbering only. Auto-detecting which shape a document is would silently produce bad locators when it guessed wrong — and this project already rejects silent automated guessing wherever correctness matters (ADR-0010 rejects model-written citations for the same reason: a wrong-but-plausible result is worse than an obviously-missing one). The person adding a document is already reading it once to write its title/publisher/`supersedes` metadata (ADR-0013); naming its structure at the same time costs nothing extra there and is far cheaper than debugging silently-wrong citations later.
