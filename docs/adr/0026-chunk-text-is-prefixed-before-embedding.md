# Chunk text is prefixed with "search_document: " before embedding

`embed.py` prepends the literal string `"search_document: "` to a Chunk's text immediately before sending it to `nomic-embed-text`, never persisting the prefixed form — `chunks.text` stays exactly as ingested; the prefix exists only for the instant of the embedding call itself.

`nomic-embed-text` is trained with an asymmetric convention: text being stored for later retrieval should be embedded with a `"search_document: "` prefix, and a query embedded at search time should instead use `"search_query: "` — the model was trained to treat the two roles differently in vector space, and skipping or misusing this measurably hurts retrieval quality. Nothing about this is discoverable from the code itself: a future reader (including a future session working on the retrieval issue) would very plausibly see a hardcoded string being prepended to text before an API call and "clean it up" as dead weight, not realizing it's load-bearing for the model's actual behavior. Recording it here is what stops that. The cost of getting this wrong now would also be a full, wasted re-embedding pass over the whole corpus once discovered later — cheap to get right at the source, expensive to fix retroactively.
