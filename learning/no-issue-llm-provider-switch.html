Switching the chat model between Ollama and OpenAI

No issue number: branch llm-provider-switch, made from a question — "how do I use my OpenAI credit instead of the local model?"

What the project is

RegDocs Assistant answers questions about regulatory documents. You ask "how much notice must a firm give?" and it finds the relevant passages, writes an answer that cites them, and has a second model check the answer against those passages. Every run is stored as an Event: an audit record of the question, the answer and each Step taken.

The concept: two different kinds of model

Concept

The app uses language models for two different jobs, and they are not interchangeable.

Embedding model (nomic-embed-text): turns text into a list of 768 numbers, a vector that captures meaning. Chunks are embedded once and stored; a question is embedded at query time, and the database finds the stored vectors nearest to it. This is the "R" (retrieval) in RAG, retrieval-augmented generation: look up relevant text first, then let a model write an answer from it.

Chat model (qwen2.5:7b-instruct): reads text and writes text. Here it plays three roles: an injection classifier (is this question an attack?), the drafter, and the judge that checks the draft.

.NET analogy: the embedding model is like the hash function behind an index. You must use the same function to write and to look up, or nothing matches. The chat model is like a service behind an interface: any implementation will do.

Where things stood

All three chat roles were hard-wired to ChatOllama, a model running on your own PC. That is free but slow, and a 7B model is a weak judge. You have about €5 of OpenAI API credit and wanted to use it.

The problem and the core idea

Swapping the chat models is easy, because LangGraph only sees a common "chat model" interface. Swapping the embeddings is not: the database column is vector(768), and OpenAI's embeddings are a different size in a different "space". You would have to re-embed everything and re-measure retrieval quality. So the idea is a hybrid: retrieval stays local, only the chat roles can move to OpenAI, and one setting chooses.

$env:LLM_PROVIDER = "openai"      # or "ollama" (the default)
$env:OPENAI_API_KEY = "sk-..."
uvicorn regdocs_track_b.api:create_default_app --factory

Or put those two lines in a .env file at the repo root (it is gitignored, so it is never committed). The app reads it at startup using python-dotenv; a variable already set in your terminal wins over the file. Your key lives in one local file instead of being retyped each session.

What the code now does

1. A factory picks the model. models.py reads LLM_PROVIDER once at startup and builds the right chat object. Bad settings fail immediately with a readable message, not on the first question:

LLM_PROVIDER=carrier-pigeon  -> ValueError: unknown LLM_PROVIDER 'carrier-pigeon'; expected one of: ollama, openai
LLM_PROVIDER=openai, no key  -> ValueError: LLM_PROVIDER=openai needs OPENAI_API_KEY to be set
JUDGE_MODEL=qwen2.5:7b-instruct (with openai) -> ValueError: no price for OpenAI model 'qwen2.5:7b-instruct' ...

The last one matters: a JUDGE_MODEL left over from an Ollama session would otherwise send a nonsense model name to OpenAI, and you would find out only after paying for the draft call.

2. Cost is real now. Every Step used to be stamped cost: 0. For a paid model that would be a false entry in an append-only audit table. Each OpenAI reply carries token counts (usage_metadata), so cost_of multiplies them by a hand-kept price table (USD per million tokens; input and output are priced differently):

1,200 input tokens x $0.15/M  +  300 output tokens x $0.60/M  =  $0.00036
Concept: tokens

Models read and bill in tokens, pieces of text roughly three-quarters of a word long. Output tokens cost more than input tokens. Tokens are not embeddings: embeddings are the vectors above.

Local Ollama models are not in the table, so they still cost 0. The OpenAI provider refuses a model that is not in the table, so a paid Step can never record 0 by accident. The prices are typed in by hand, so check them against OpenAI's pricing page.

3. Provider failures become a 502. If OpenAI rejects the key, the credit runs out, or you are rate-limited, the OpenAI library raises an APIError. Before, only Ollama's ResponseError was turned into HTTP 502 ("the model server failed"); an OpenAI error would have been a 500, which looks like a bug in our own code. PROVIDER_ERRORS now covers both.

A deliberate asymmetry

The verify Step still tolerates only Ollama's abort (a small model looping forever). An OpenAI error in the judge fails the whole request. That is on purpose: an exhausted quota should be loud, not disguised as a low-confidence answer. It does mean the draft call was already paid for. See ADR-0036.

About the tests

You asked for no mocks, only tests of the complete pipeline. So these tests build the same app uvicorn builds and send real requests. That has a cost: the happy-path runs need Ollama, Postgres and (for OpenAI) your key plus a fraction of a cent, so they are opt-in. Five cheap checks run by default (bad provider, missing key, unpriced model, and two for the .env file). The bad-key test is a real call to OpenAI that is refused for free.

Not yet run

The two happy-path tests were written but not run when this was built, because Ollama, Docker and an API key were not available in that session. Run them once before trusting the cost numbers.

Try it yourself

The one test that best teaches the process is the bad-key test: it makes a genuine network call, the failure comes from OpenAI itself, and the app turns it into a 502.

$env:RUN_REAL_OPENAI = "1"
python -m pytest track-b/tests/test_provider_pipeline.py::test_openai_rejecting_the_key_is_a_502_not_a_500

It needs only the internet: no Ollama, Postgres or credit, because it fails at the first Step (classify). To poke at it, change PROVIDER_ERRORS = (ResponseError, APIError) in models.py to (ResponseError,) and rerun. It now fails with a 500, which is what a dead key would have produced before this change. Put it back afterwards.

For a no-dependency one, run python -m pytest track-b/tests/test_provider_pipeline.py::test_an_openai_model_with_no_price_stops_the_app_starting. It shows the startup check; delete the price check in build_chat_model and it fails. These two were chosen over the rest because each shows a failure caught early and clearly rather than late and confusingly. Once Ollama, Postgres and your key are set up, the two happy-path tests are the ones to run (RUN_REAL_PIPELINE=1, plus RUN_REAL_OPENAI=1 and OPENAI_API_KEY for the OpenAI one).

Summary

One environment variable, LLM_PROVIDER, now chooses whether the classifier, drafter and judge run on local Ollama or on OpenAI, while embeddings and retrieval stay local because the stored vectors are tied to one embedding model. Paid Steps record their estimated dollar cost, unpriced models are rejected at startup, and OpenAI failures return a 502 instead of a 500. The prompts were tuned on the local model, so treat the first OpenAI run as a new baseline.
