Issue #42, explained from the start

What the app is, what was missing, and what these changes add. No prior AI knowledge needed.

1. What is this project?

RegDocs Assistant answers questions about Irish financial-regulation documents. You ask "What must a firm disclose?" and it replies with an answer and shows where in the real documents the answer came from. In a regulated setting, an answer you can't check is worthless.

Concept: RAG (Retrieval-Augmented Generation)

An AI language model (an "LLM") writes fluent text but doesn't know your documents. If you just ask it, it may invent a plausible answer. RAG fixes that with two moves:

  1. Retrieve: search your documents for the few passages most relevant to the question.
  2. Generate: paste those passages into the prompt and tell the model "answer using only these."

It's like an open-book exam: the model gets the relevant pages put in front of it instead of answering from memory.

A Chunk is one of those passages: a clause or numbered section cut out of a regulatory Document. Each Chunk has a locator, like "Section 4.2", that says where it lives in the original.

2. Where we were before this issue

Earlier issues built a pipeline of four steps. It's a "graph" (a flowchart that code runs) built with a library called LangGraph:

1. classify stub (does nothing real yet)
2. retrieve real: searches the database for relevant Chunks
3. draft asks the AI model to write the answer. This is what issue #42 changes.
4. verify stub (does nothing real yet)

Before #42, draft was a placeholder. It pasted the Chunk text into a prompt and returned whatever the model said. That left two gaps:

  • No citations. The answer was just text. Nothing said which Chunk supported which claim.
  • The prompt was a string buried in code. It was hard to version, compare or reuse later.

3. The big idea: don't let the AI write citations

The tempting but wrong approach

Tell the model: "cite the section number, e.g. Section 4.2." Models are good at producing text that looks right. It might write "Section 4.7", which sounds fine and doesn't exist. A wrong citation that looks real is worse than no citation. The project's decision record (ADR-0010) rules this out.

The approach used instead

Number the Chunks in the prompt: [1], [2], [3]. The model only has to write those small numbers. Then our own ordinary code looks up what [2] really is and attaches the real document id and locator. The model never types a section number.

You know this pattern: it's like the model handing back a foreign-key id, and your code doing the join to get the real row. The model can pick a wrong id, but it can't forge the content behind a valid one.

4. What the model sees now

The new file track-b/prompts/draft-v1.txt is the prompt template. After filling in the blanks, the model receives something like this:

You answer questions about Irish financial-regulation documents
using only the numbered excerpts below.

Rules:
- Use only information in the excerpts. If they do not answer the
  question, say so plainly.
- After each claim, cite the excerpt that supports it with its
  number in square brackets, like [1].
- Cite only numbers that appear below. Never write section numbers,
  clause numbers or document names yourself.

Excerpts:

[1] A firm must keep records for six years.

[2] A firm must give 30 days' written notice before a fee waiver.

[3] Complaints must be acknowledged in five days.

Question: How long must records be kept?
Answer:

A good reply would be: "Records must be kept for six years [1]."

Concept: prompt versioning

The prompt lives in a file, draft-v1.txt, not inside the Python. A new wording becomes draft-v2.txt next to it, and the old one stays readable. The project's "Replay" feature re-runs old questions, so you need to be able to say which prompt produced which answer. It's the same idea as database migrations: never edit history, add a new one.

Also, build_graph reads this file once at startup. If the file is missing you find out immediately, not on the first user question.

5. What the code does with the model's reply

The new function _resolve_citations in track-b/graph.py scans the answer for markers like [2] using a regular expression, then handles each one:

Marker in the answerWhat happens
[2], with 3 Chunks retrievedValid. Look up Chunk 2 and add a Citation holding its chunk_id, document_id and locator. The marker stays in the text.
[2] written twiceOnly one Citation is recorded. Duplicates are skipped.
[9], with only 3 ChunksInvalid. The model made it up. The marker is removed from the text and no Citation is created. We drop it rather than guess.
[0]Also invalid, because numbering starts at 1.

A bad marker is removed along with the space next to it, so the sentence doesn't end up as "six years ." or start with a stray space.

Example. The model replies "Keep records for six years [1] and notify in 90 days [9]." After resolution:

answer    = "Keep records for six years [1] and notify in 90 days."
citations = [{ "marker": 1,
               "chunk_id": "c-1",
               "document_id": "doc-a",
               "locator": "4.2" }]

6. Two small details worth knowing

  • Empty answers are still an error. If the answer is empty after stripping (say, it was only [9]), or the model returned something that isn't plain text, draft raises an error. The Event schema requires a non-empty answer, so it's better to fail loudly than store junk.
  • Citations aren't in the Event. The shared Event schema has no field for them yet, so they travel in the graph's final state (final["citations"]) instead. Adding a field is a separate decision.

8. Why were there tests with a real model?

Most tests use a fake model that returns a scripted answer such as "...[9]". That proves our code handles good and bad markers correctly. But it can't prove a real model will actually write [1] when asked. So there's one opt-in test using a real local model, qwen2.5:7b-instruct (run through Ollama on your machine, so it costs nothing). It's off by default because it needs Ollama installed and the model downloaded (about 4.7 GB).

Concept: why test the model separately?

Your own code is deterministic, so a fake model is enough to test it. A real model is non-deterministic and might ignore instructions. Two kinds of test answer two different questions: "is my code right?" and "does the model do what I asked?"

9. Try it yourself

Two tests teach the whole process

Both are in track-b/tests/test_draft_citations.py, and both use a scripted fake model, so nothing else needs to be running. Together they show the good case and the bad case:

  1. test_markers_resolve_to_the_document_and_locator_of_the_numbered_chunk: the model answers "Give 30 days' notice [1] and disclose fees [2]." and you see each marker turned into a Citation holding the real chunk id, document id and locator.
  2. test_out_of_range_markers_are_not_cited_and_are_stripped_from_the_answer: the model answers with [0], [9] and [3] (only two Chunks exist). Only the valid [1] becomes a Citation, and the bad markers vanish from the answer text.
python -m pytest track-b/tests/test_draft_citations.py::test_markers_resolve_to_the_document_and_locator_of_the_numbered_chunk track-b/tests/test_draft_citations.py::test_out_of_range_markers_are_not_cited_and_are_stripped_from_the_answer -v

To see it for yourself, change the fake answer in the first test (for example [1] to [7]) and watch it fail, then compare the answer text with the second test. Undo the change afterwards.

Why these two: the rest of the tests cover edge cases of the same idea (duplicates, the prompt file, blank answers). These two show the core idea: valid markers become verified Citations, and made-up ones never reach the user.

10. The whole thing in one paragraph

Before, draft sent loose text to a model and got loose text back. Now it sends numbered excerpts using a versioned prompt file, the model answers with [n] markers, and plain code turns each valid marker into a verified Citation pointing at a Chunk that was genuinely retrieved. Invalid markers are stripped. The model never writes a locator, so a made-up citation can't reach the user.
